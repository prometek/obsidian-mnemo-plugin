## Architecture

This is a TypeScript **Obsidian plugin** that acts as the UI layer for [`obsidian-mnemo`](https://github.com/prometek/obsidian-mnemo), a Python MCP server exposing vault operations (read, write, semantic search via ChromaDB + sentence-transformers).

### IPC: plugin ↔ obsidian-mnemo

- The plugin spawns `obsidian-mnemo --vault <path>` at `onload()` — SSE transport on `http://127.0.0.1:8765`.
- Bearer token is read at runtime from `~/.obsidian-mnemo/config.json` (auto-generated by the server, never stored in plugin `data.json`).
- All HTTP calls to the server go through `src/services/mnemoClient.ts` exclusively.
- Process lifecycle (spawn, health-check, kill) is managed by `src/services/serverManager.ts`.
- If port 8765 is already in use, the plugin reuses the running instance — this is intentional, enabling Claude Desktop / Cursor to share the same server while Obsidian is open.

### Key architectural constraints

- Never import from `obsidian` inside `src/services/` or `src/utils/` — keep them framework-agnostic so Vitest can test them without mocking the Obsidian API.
- Settings use `loadData()` / `saveData()` (Obsidian API) → `data.json`. Merge pattern: `Object.assign({}, DEFAULT_SETTINGS, await this.loadData())`.
- Build output: esbuild → single `main.js` at repo root.

## Tooling (once package.json exists)

| Task | Command |
|------|---------|
| Build (dev, watch) | `npm run dev` |
| Build (production) | `npm run build` |
| Type check | `npx tsc --noEmit` |
| Lint | `npx eslint src/` |
| Format | `npx prettier --write src/` |
| Tests | `npx vitest` |
| Single test file | `npx vitest run src/services/mnemoClient.test.ts` |
